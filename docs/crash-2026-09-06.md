# Project Monitor crash: 2026-09-06, 15:45:07 WIB

Confirmed from systemd-coredump PID 746692, running the Project Monitor launcher:

- Signal SIGABRT, through `pyqt6_err_print`, `PyQtSlotProxy::unislot`, and `QTimer::timeout`.
- The core retained a Python traceback through `ui.py:975`, `_tick`, and
  `app/db.py:105`, `get_all_accounts` (line numbers before this fix).
- Exception: `sqlite3.ProgrammingError: Cannot operate on a closed database`.

The one-second refresh callback accessed SQLite after the connection had closed.
The old shutdown code closed the database without stopping this timer. This is an
application shutdown defect. The core does not establish that being offline caused
that shutdown. Login-status timeouts were already caught in the previous code;
they were not confirmed as the cause of this abort.

The other Python core at 07:11:47 came from the earlier headless GUI test setup.
No OOM kill was found in the examined incident timeline. Current memory availability
does not establish memory usage at the time of the crash. The account database
passes SQLite `PRAGMA quick_check`; this establishes integrity, not a full data-loss
audit. The app does not remove Codex conversation files during account rotation.

Fixes: stop the UI timer before closing SQLite, ignore late refresh callbacks,
contain unexpected timer errors, and preserve diagnostic logs across reboot.
Separate offline improvements move CLI work off the GUI thread, reduce status
polling, check reachability before account mutation, and avoid explicit logout
before replacement login.

Temporary core copies used for inspection were deleted immediately. No credentials
or core-memory contents were saved in this report.
